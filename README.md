# משק 32 – חסטולרו

אתר הזמנות בעברית וב־RTL למשק משפחתי. הפרויקט מחולק ל־Frontend ב־React/TypeScript ול־Backend ב־Java/Spring Boot.

## מה כבר עובד

- הזמנה כאורחת עם שם וטלפון הנשמרים במאגר לקוחות.
- קטלוג, סל, מגבלות כמות ובדיקת זמינות בצד השרת.
- יצירת הזמנה אמיתית ושמירת פרטי נקודת האיסוף והדרך המבוקשת לתשלום.
- מסך מנהל מוגן ונפרד ב־`/admin`: בחירה בין ניהול מוצרים לבין ניהול הזמנות, סינון לפי לקוח, מוצר, נקודת חלוקה ואריזה; עדכון סטטוס, תיבת "נארזה", הערות ומאזן.
- בחירת Bit/PayBox מסומנת במערכת, ללא קישור או אימות תשלום עד לחיבור לספק תשלומים רשמי.
- חנות נפרדת לכל נקודת איסוף: לכל חנות כתובת, קטלוג, זמינות ומחירים משלה, תחת אותו מסך מנהל.
- חנות ראשונה מוכנה: **איסוף מהחנות שלנו**, מושב ציפורי. מנהל יכול להוסיף לה מוצרים, מחיר, קטגוריה, מגבלת כמות וקישור לתמונה.

## הפעלה מקומית

1. פתחי PowerShell בתיקיית הפרויקט והגדירי פרטי מנהל זמניים לסשן המקומי:

```powershell
$env:ADMIN_USERNAME = "admin"
$env:ADMIN_PASSWORD = "בחרי-סיסמה-חזקה-מקומית"
```

2. הפעילי את ה־Backend. אם Maven לא מותקן, אפשר להשתמש ב־Maven Wrapper; ב־Windows מסוים יש צורך ב־Maven מקומי.

```powershell
cd backend
.\mvnw.cmd spring-boot:run
```

3. בחלון נפרד הפעילי את ה־Frontend:

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

4. פתחי `http://127.0.0.1:5173/store/zippori-store` לחנות של מושב ציפורי, או `http://127.0.0.1:5173/` לאותה החנות כברירת מחדל. ממשק המנהל נמצא ב־`http://127.0.0.1:5173/admin`.

## חנויות ונקודות איסוף

הכתובת של כל חנות משתמשת ב־slug, למשל `store/zippori-store`. כאשר מוסיפים בעתיד נקודת איסוף חדשה, יוצרים לה slug חדש וקטלוג נפרד. כך אפשר למכור אותו מוצר במחיר אחר בכל נקודת איסוף, אך לראות את כל ההזמנות והמאזן יחד במנהל.

לתמונות: במנהל בוחרים קובץ תמונה מהמחשב בעת הוספה או עריכה של מוצר. הקובץ נשמר מקומית ב־`backend/uploads/` (תיקייה שאינה נכנסת ל־Git); הגודל המרבי הוא 5MB.

## מסד נתונים

בפיתוח השרת משתמש ב־H2 מקומי; הקובץ שלו נשמר ב־`backend/data/` ואינו נכנס ל־Git. בפריסה משתמשים בפרופיל `prod` ומספקים PostgreSQL באמצעות משתני הסביבה שב־`.env.example`.

## פרסום חינמי זמני

אפשר לפרסם את האתר תחילה בכתובת חינמית, בלי לקנות דומיין. כדי שההזמנות והמנהל יעבדו גם מחוץ למחשב, מפרסמים שני חלקים: את ה־Frontend כאתר סטטי ואת ה־Backend עם PostgreSQL. שירותים כגון Render מציעים מסלולים חינמיים, אך הם מתאימים לניסוי ולהתחלה בלבד ועלולים להיות איטיים לאחר זמן ללא שימוש.

לפני הפרסום מגדירים בשירות האחסון:

- ב־Backend: `SPRING_PROFILES_ACTIVE=prod`, פרטי ה־PostgreSQL הפנימיים של Render (`DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USERNAME`, `DATABASE_PASSWORD`), וכן `ADMIN_USERNAME`, `ADMIN_PASSWORD` ו־`FRONTEND_ORIGIN` (הכתובת החינמית של האתר).
- ב־Frontend: `VITE_API_URL` עם כתובת ה־Backend הציבורית ואחריה `/api`.

לעולם לא שומרים סיסמת מנהל או פרטי מסד נתונים בקוד או ב־Git. כאשר נרצה להשיק, אפשר לחבר לאותה פריסה דומיין בתשלום בלי לשנות את האתר.

## אבטחה

שם וטלפון מזהים לקוח אך אינם התחברות מאובטחת. לפני פתיחת חשבונות לקוח יש להוסיף קוד חד־פעמי ב־SMS. נתיבי המנהל מאומתים בשרת, ויש להגדיר את פרטי הגישה רק במשתני סביבה.
